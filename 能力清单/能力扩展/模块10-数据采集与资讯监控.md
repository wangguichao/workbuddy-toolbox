### 22. 爬取行业公开行情数据，每日更新保存至 Excel 表格

**细分能力点（5 条）**

1. 支持股票、基金、期货、加密货币、大宗商品等常见公开行情源，按标的批量拉取。
2. 用 akshare / yfinance / tushare 等免费库获取日线行情，字段含日期、开盘、收盘、最高、最低、成交量。
3. 每日定时自动更新，新数据追加到 Excel 而非覆盖，完整保留历史记录。
4. 自动去重（按日期+代码）、补全缺失数据、标注"最后更新时间"，保证表格干净可查。
5. 可对多只标的多 Sheet 存放，并自动生成涨跌幅统计与周/月汇总。

**可执行提示词（5 条）**

1. "用 Python 的 akshare 库，抓取沪深300成分股的每日收盘价和成交量，保存到 D:\行情数据\stock_daily.xlsx，每天更新时把新数据追加到末尾。"
2. "写个脚本，每天下午 5 点自动刷新 D:\行情数据\ 里的 Excel，保留最近 3 个月数据，老数据不要删，只追加新的。"
3. "抓取黄金、原油、比特币这三种资产的日 K 线数据，更新到 D:\行情数据\commodity.xlsx，按日期追加，字段要有日期、收盘价、涨跌幅。"
4. "用 schedule 库设置每个工作日 9:30 前自动拉取开盘行情更新 Excel，更新完成后通过 Server酱给我发一条'已更新'的确认消息。"
5. "对比 D:\行情数据\stock_daily.xlsx 里最近两个交易日的数据，把涨跌幅超过 3% 的标的用黄色高亮标出来，生成一个汇总 Sheet。"

**操作步骤（10 步）**

1. 安装 Python 3.10+，执行 `pip install akshare pandas openpyxl schedule requests` 安装所需库。
2. 确认数据源：优先用 akshare 免费公开接口或交易所官网公开数据，阅读数据使用条款，遵守 robots 协议与访问频率限制（建议单标的每分钟不超过 1 次请求）。
3. 先用小样本测试接口：`ak.stock_zh_a_hist()` 拉取一只股票近 10 个交易日数据，打印出来核对字段。
4. 编写主脚本：遍历标的代码列表，循环拉取数据，统一字段名为 日期/代码/名称/开盘/收盘/最高/最低/成交量。
5. 用 pandas 处理：按 `日期+代码` 去重（`drop_duplicates`），与历史数据 `concat` 合并，缺失交易日用 `ffill` 或标记补全。
6. 写入 Excel：用 `pandas.ExcelWriter` 为每类资产建一个 Sheet，表头固定，追加新行并保留原格式。
7. 加异常处理：网络断开或接口限流时自动重试（最多 3 次），仍失败则记录日志、跳过当天，不影响已保存数据。
8. 用 `schedule` 库写定时循环（如 `schedule.every().day.at("17:00")`），并通过 Windows 任务计划程序添加开机自启或每日计划任务。
9. 配置日志：记录每次更新的时间、成功/失败条数，方便排查接口变动。
10. 先连续跑一周验证数据准确率与格式无误，再接入微信推送摘要（Server酱），正式投入日常使用。

### 28. 监控指定商品电商价格，降价自动弹窗 + 微信消息提醒

**细分能力点（5 条）**

1. 同时监控京东、淘宝/天猫、拼多多等平台的指定商品链接，按链接独立跟踪价格。
2. 支持设置目标价与降价阈值，触发条件满足时自动发出提醒。
3. 双通道提醒：Windows 桌面弹窗通知 + 微信消息（Server酱/企业微信 webhook）。
4. 每次抓取价格写入历史记录 Excel，可生成单商品价格走势与降价幅度统计。
5. 多商品并行监控互不干扰，失效链接自动标记并提示人工更新。

**可执行提示词（5 条）**

1. "监控这三个京东商品链接：https://item.jd.com/111111、https://item.jd.com/222222、https://item.jd.com/333333，目标价都是 1500 元，只要低于 1500 就通过 Server酱推送到我的微信，消息里带上商品名和当前价。"
2. "每 30 分钟检查一次这几个商品的价格，只要比上一次记录降价超过 5%，就用企业微信 webhook 发一条消息给我，附上商品链接和当前价格。"
3. "把每次抓到的价格追加保存到 D:\价格监控\price_history.xlsx，每天生成一张价格趋势图（折线图）存在同目录。"
4. "先试运行一次：抓取这个链接 https://item.jd.com/111111 的当前价格，告诉我现在的价格和上次记录的价格差多少钱。"
5. "帮我盯三样东西：iPhone 16 Pro、美的空气炸锅、星巴克咖啡豆，降价时弹出 Windows 桌面通知，同时推微信，别重复推送同一价格。"

**操作步骤（10 步）**

1. 安装 Python 及 `pip install requests beautifulsoup4 schedule openpyxl plyer`（plyer 用于桌面弹窗）。
2. 用浏览器打开商品页，按 F12 打开开发者工具，在 Network 里找价格接口，或直接分析 HTML 中价格所在节点；电商平台反爬严格，先看 robots 与页面协议，务必控制抓取频率。
3. 编写抓取函数：优先用 `requests` 带常见浏览器 User-Agent 请求，用 BeautifulSoup 解析价格与标题；若页面动态加载，改用 Selenium + Edge WebDriver 渲染后提取。
4. 将抓取结果写入 `price_history.xlsx`（列：时间、商品、平台、价格、链接），读取上次价格并计算涨跌幅。
5. 判断触发条件：`当前价 <= 目标价` 或 `跌幅 >= 阈值`（如 5%），满足则进入提醒环节。
6. 桌面弹窗：用 `plyer.notification.notify()` 弹出 Windows 通知，标题"降价提醒"，正文含商品名与价格。
7. 微信推送：注册 Server酱（sct.ftqq.com）拿到 sendKey，或建企业微信群机器人拿 webhook，用 `requests.post()` 发送文本消息。
8. 防止重复推送：用字典记录"商品-价格"最近一次已推送的状态，同一价格不重复提醒。
9. 用 `schedule.every(30).minutes` 设置轮询，再通过 Windows 任务计划程序开机自启，断线自动重启脚本。
10. 先设一个较高的测试阈值跑半天，确认弹窗和微信都正常，再改回真实目标价；每周清理失效链接，更新商品 URL。

### 35. 每日定时抓取新闻行业资讯，整理精简阅读简报推送

**细分能力点（5 条）**

1. 支持多信息源：RSS/Atom 订阅、新闻网站列表页、微信公众号文章链接，统一采集。
2. 自动去重（标题/URL 判重）、过滤标题党与无关内容、提取发布时间。
3. 用 AI 大模型或关键词规则为每条新闻生成一句话摘要，并按主题/重要度归类。
4. 生成精简阅读简报（10~15 条），Markdown 格式含标题、摘要、原文链接。
5. 每日定时推送至微信（Server酱/企业微信）或邮箱，并本地存档便于回看。

**可执行提示词（5 条）**

1. "每天早上 8 点，抓取这几个 RSS 源的新闻：36氪、IT之家、华尔街见闻，整理成 10 条科技行业简报，通过企业微信 webhook 推送到群里。"
2. "抓取这几个行业网站的新闻列表，去掉重复的和标题党的，给每条生成一句话摘要，按'重要/一般'分类，整理成 Markdown 简报文件。"
3. "把今天和 AI 相关的行业新闻汇总成一份 200 字以内的晨报，用 Server酱推送到我的微信，晨报里每条附上原文链接。"
4. "现在手动运行一次抓取脚本，把最近 24 小时的新增新闻生成简报，保存到 D:\新闻简报\2026-08-19.md。"
5. "简报排版规则：重点新闻加粗并在最前面，每条格式为『标题 —— 一句话摘要 —— 原文链接』，控制在 15 条以内。"

**操作步骤（10 步）**

1. 收集目标行业的信息源：找到各大媒体的 RSS/Atom 订阅地址，没有 RSS 的就保存官网新闻列表 URL，整理成一个 `sources.txt` 清单。
2. 安装 Python 及 `pip install feedparser requests beautifulsoup4 schedule openpyxl`。
3. 编写采集脚本：用 `feedparser.parse()` 解析 RSS，或 `requests` + BeautifulSoup 解析新闻列表页，提取标题、链接、发布时间、摘要字段。
4. 按 URL/标题去重，用发布时间过滤 24 小时内的新闻，去掉明显无关与营销软文。
5. 调用 AI 生成摘要：接入大模型 API（如 DeepSeek/通义/本地模型），构造 prompt"为下面新闻各生成一句话摘要并按主题分类"，或先用关键词规则粗分类。
6. 按主题分组、按重要度排序，组装成 Markdown 简报（标题加粗 + 一句话摘要 + 原文链接）。
7. 保存简报到 D:\新闻简报\ 目录（文件名含日期），同时推送：企业微信 webhook 发 Markdown，或 Server酱发文本到微信。
8. 用 `schedule` 设置每天 8:00 与 18:00 两个时段，再通过 Windows 任务计划程序保证开机后持续运行。
9. 加失败重试与日志：单个源失效自动跳过并记录，接口报错延迟 10 分钟重试。
10. 每周回看简报质量，增删信息源、优化摘要 prompt 和分类规则，保持推送内容精简有价值。

### 39. 编写自动化爬虫脚本，抓取公开展会、招聘、房源信息

**细分能力点（5 条）**

1. 可配置化抓取目标：公展会、招聘、房源等公开信息网站，一套脚本适配多类站点。
2. 支持两种页面模式：静态页面用 requests + BeautifulSoup，动态页面用 Selenium 渲染。
3. 提取结构化字段：展会（名称/时间/地点/官网）、招聘（职位/公司/薪资/城市）、房源（标题/价格/户型/小区）。
4. 增量抓取：按标题+链接去重，新记录追加到 Excel/CSV，避免重复积累。
5. 定时运行 + 随机延时 + User-Agent 轮换 + 失败重试 + 日志，稳定不封号。

**可执行提示词（5 条）**

1. "写一个爬虫抓取这个展会信息页 https://example.com/exhibitions，提取展会名称、开始时间、结束时间、举办地点、官网链接，保存到 D:\信息采集\展会.xlsx，按开始时间排序。"
2. "抓取 BOSS直聘 / 拉勾网上'数据分析师'岗位的前 5 页，字段：职位名称、公司、薪资、城市、经验要求、链接，存到 Excel 里按薪资从高到低排序。"
3. "用 Selenium 抓取这个动态加载的房源网站首页列表，提取标题、价格、户型、面积、小区、链接，保存到 D:\信息采集\房源.xlsx。"
4. "做一个通用爬虫，每天 9 点自动运行，把新增的展会/招聘/房源记录增量追加到对应的 Excel，已存在的不要重复写入。"
5. "跑一次抓取任务，把失败的链接、被跳过的条目和原因写进 D:\信息采集\crawl_log.txt，抓取完统计新增了多少条。"

**操作步骤（10 步）**

1. 抓取前先访问目标站点根目录下的 robots.txt，确认是否允许爬取，并阅读网站用户协议，只采集公开信息，控制请求频率，禁止抓取登录后/付费内容。
2. 安装 Python 及 `pip install requests beautifulsoup4 lxml selenium openpyxl`；若用 Selenium，下载与 Edge/Chrome 版本匹配的 WebDriver。
3. 用浏览器 F12 开发者工具分析页面结构：定位列表容器、每条记录节点、各字段的 CSS 选择器或 XPath，确认翻页 URL 规则。
4. 编写配置驱动的爬虫类：`crawl(url, item_selector, fields)`，字段选择器写在外置配置 dict 中，换站点只需改配置。
5. 静态页面用 `requests.get()` + BeautifulSoup 解析；动态加载页面用 Selenium 打开、滚动到底触发懒加载再取 HTML。
6. 用正则/选择器提取字段并清洗：去空白、统一日期格式、薪资单位统一为"元/月"、价格统一为数字。
7. 增量去重：读入已有 Excel，按"标题+链接"生成集合，本次抓取只追加不存在的记录。
8. 用 openpyxl 写入 Excel，按栏目分 Sheet，附上"抓取时间"列；超大批量可改用 CSV。
9. 控制频率：每次请求之间加 1~3 秒随机延时，轮换 3~5 个 User-Agent，用 `schedule` + Windows 任务计划程序设为每日 1 次。
10. 加 try/except 与日志，站点改版导致选择器失效时按日志定位并更新配置；上线前先跑小规模测试核对字段准确性。

### 58. 定时抓取天气预报，生成出行提醒发送至私人微信

**细分能力点（5 条）**

1. 获取指定城市未来 3~7 天天气：气温、天气现象、风力、降雨概率、空气质量。
2. 结合出行时间自动生成提醒：穿衣建议、是否带伞、是否适合户外活动、限行提示。
3. 每日早晚定时推送至私人微信（Server酱/企业微信 webhook）。
4. 支持多城市监控（如家与公司两地），自动选择对应城市推送。
5. 恶劣天气自动升级提醒：暴雨、高温、寒潮、雾霾等预警时提前加推一条。

**可执行提示词（5 条）**

1. "每天早上 7 点获取上海未来 3 天天气预报，生成今天的出行提醒：最低最高温度、天气现象、要不要带伞、空气质量指数，通过 Server酱推送到我的微信。"
2. "每天 6:30 推一次北京当天天气，22:00 再推一次明天天气（含降雨概率和风力），都发到我的微信。"
3. "抓取上海、苏州两个城市的未来 7 天天气，追加保存到 D:\天气\weather_history.xlsx 备查。"
4. "如果明天降雨概率超过 50%，或者最高气温超过 35 度，就额外在早上 6 点提前发一条加急提醒。"
5. "生成一份简洁的今日出行提醒，格式：『上海 8/19 多云 24~32°C，东南风3级，降水20%，建议穿短袖+薄外套，降水概率低可不带伞』，推到我微信。"

**操作步骤（10 步）**

1. 选择天气数据源：推荐和风天气（dev.qweather.com）或高德开放平台天气接口，注册账号免费获取 API Key；注意免费版调用次数限制。
2. 安装 Python 及 `pip install requests schedule openpyxl`。
3. 阅读 API 文档，确认城市编码（如上海 101020100）与返回字段：温度、天气代码、风力、相对湿度、降水概率、AQI。
4. 编写脚本：`requests.get()` 调用天气 API，解析 JSON，把关键字段整理成字典；请求失败自动重试 3 次。
5. 用规则生成出行建议：气温 22~28°C 建议短袖，低于 15°C 建议加外套，降雨概率 ≥40% 建议带伞，AQI>150 建议戴口罩减少户外。
6. 将当天数据追加到 `weather_history.xlsx`（列：日期、城市、最高温、最低温、天气、风力、降雨概率、AQI）。
7. 推送渠道：Server酱发送文本，或企业微信机器人 webhook 发送 Markdown；把提醒文本按行组织成易读格式。
8. 用 `schedule` 设置 6:30 与 22:00 两个定时任务，再通过 Windows 任务计划程序设为开机自启、断线自动重启。
9. 配置恶劣天气加急：当天 API 返回暴雨/高温/寒潮预警码时，额外发一条加急提醒到微信。
10. 连续测试 3 天：核对推送时间是否准时、内容字段与官方天气是否一致、多城市推送是否正确，再正式使用。

3. 用 F12 分析列表页结构：定位房源条目节点与字段选择器，确认翻页参数与排序规则；动态加载页用 Selenium 渲染。
4. 编写脚本循环翻页抓取，字段：标题、价格、户型、面积、小区、区域、是否近地铁、发布时间、链接。
5. 数据清洗：统一价格单位（元/月）、户型格式（2室1厅）、面积单位（㎡），去空白与乱码，剔除价格<200 或面积>1000 的异常行。
6. 判重：先按"标题+链接"去重；再按"小区+户型+价格"识别重复发布，保留最早/最新一条并打标。
7. 按筛选条件过滤：价格区间、户型数量、面积范围、是否地铁房，计算性价比 `价格/面积`。
8. 用 openpyxl 生成对比清单：每行一条房源，按性价比升序排列，符合条件的高亮填充，附原文链接列；另生成一个"疑似虚假"Sheet 单独存放异常房源。
9. 用 `schedule` 设置每日定时更新，配合 Windows 任务计划程序开机自启；有新增符合条件的房源时通过 Server酱/企业微信推送提醒。
10. 线下看房前先电话核实房源真实性，验证 3~5 条记录与线上一致后，再放心按清单联系；每周清理下架与失效链接。
