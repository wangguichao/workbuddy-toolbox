### 56. 自动编写单元测试代码，适配 Java、Python、JS 开发项目

**细分能力点（5 条）**

1. 支持 Java（JUnit 5 + Maven/Gradle）、Python（pytest）、JS（Jest/Vitest）三大技术栈自动生成测试骨架。
2. 解析被测类/函数的入参、返回值、边界条件，自动推导"正常、边界、异常"三类测试场景。
3. 自动生成测试数据，含空值 null/""、越界值、极大数据、特殊字符，并计算断言预期结果。
4. 生成的测试文件放入正确目录并自动执行，输出通过/失败统计，失败用例标注失败原因。
5. 支持批量扫描整个项目目录，按包/模块结构为所有公共方法生成对应测试文件。

**可执行提示词（5 条）**

1. "读取 D:\workspace\my-service 下所有 Java 源码，用 JUnit 5 为每个公共类生成单元测试到 src/test/java，覆盖正常、边界和异常场景，断言用 Assertions。"
2. "为 C:\project\utils.py 里的每个函数用 pytest 生成测试用例，包含参数边界值、空输入、类型错误场景，写到同目录 test_utils.py，测试函数名以 test_ 开头。"
3. "给 F:\webapp\src\utils 里的时间格式化、金额计算函数用 Jest 生成测试，文件命名 *.test.js，用 describe/it/expect 组织，放到 __tests__ 目录。"
4. "为 E:\work\calc.js 的 add、divide 函数生成 Vitest 测试，补充除以零、负数、极大数用例，跑完把失败用例按函数名汇总给我。"
5. "扫描 D:\workspace 整个项目，按现有模块结构批量生成单元测试，Java 跑 mvn test、Python 跑 pytest -v、JS 跑 npm run test，输出测试报告。"

**操作步骤（9 步）**

1. 确认技术栈与构建工具：Java 看 pom.xml（Maven）或 build.gradle（Gradle），Python 看 requirements.txt 确认入口函数，JS 看 package.json 确认 scripts。
2. 安装测试框架：Java 在 pom.xml 添加 junit-jupiter 依赖后 `mvn dependency:resolve`；Python 执行 `pip install pytest`；JS 执行 `npm install -D jest` 或 `npm install -D vitest`。
3. 让 AI 助手解析源码，先列出被测函数清单（方法名、参数、返回类型、可见性），人工确认后再生成测试。
4. 按"正常/边界/异常"三档生成用例：Java 用 @Test + @DisplayName 与 @ParameterizedTest，pytest 用 assert，Jest/Vitest 用 test() + expect()。
5. 生成测试数据：包含合法值、null/"" 空值、边界极值、超大数、特殊字符，Java 可用 @ValueSource/@MethodSource 参数化传入。
6. 写入正确测试目录：Java 放 src/test/java（包结构与 main 对齐），Python 与源码同目录或 tests/，JS 用 *.test.js 命名并放 __tests__ 或 src 同层。
7. 执行测试：Java `mvn test`，Python `pytest -v`，JS `npx jest` 或 `npm run test`，观察失败用例并让 AI 修复断言或补充逻辑。
8. 查看报告：JUnit 的 target/surefire-reports、pytest 终端逐条结果、Jest 的 --coverage 覆盖率，把不通过的用例反馈给 AI 修正。
9. 对依赖数据库/网络/文件系统的代码，用 Mockito（Java）/ unittest.mock（Python）/ jest.mock（JS）打桩，让测试脱离外部依赖可独立运行。

### 68. 批量修改 CAD 图纸文字标注，统一字号、字体、颜色规范

**细分能力点（5 条）**

1. 支持遍历整个文件夹下的 DWG/DXF 图纸，批量处理文字标注对象。
2. 能区分并处理 TEXT 单行文字、MTEXT 多行文字、块参照（INSERT）内的属性文字。
3. 按图层、文字类型或样式分别设定字体、字高、颜色的统一规则。
4. 修改前自动备份原图，处理失败可回滚，避免损坏图纸。
5. 生成处理报告，统计每个文件修改文字数量及跳过项（如锁定图层）。

**可执行提示词（5 条）**

1. "用 ezdxf 批量处理 D:\cad\图纸\ 下所有 DXF 文件，把所有 TEXT 和 MTEXT 的字高统一改成 2.5，文字颜色改成黄色。"
2. "用 pyautocad 打开 F:\设计图\ 里的 DWG 图纸，把所有标注文字字体改成宋体、字高统一 3，图层为 dim 的文字标成红色。"
3. "扫描 C:\cad_files 里所有图纸，把字高小于 2 的文字统一改为 3，先备份到 D:\cad\backup\ 再改，改完生成修改清单。"
4. "批量修改 D:\cad\图纸\ 内所有块参照的属性文字，字高统一 2.5、字体用仿宋，处理后按文件输出修改数量报告。"
5. "把 E:\工程图 中文字按图层统一规范：尺寸标注蓝色、文字注释绿色、标题黄色，全部改为 Arial 字体，字体高度不小于 2.5。"

**操作步骤（9 步）**

1. 安装 Python 及库：`pip install ezdxf`；处理 DWG 需另装 `pip install pyautocad`（依赖 pywin32 和本机已装 AutoCAD）。
2. 确认图纸格式：DXF 可直接用 ezdxf 读取；DWG 用 pyautocad 调 AutoCAD 处理，或先用 AutoCAD 另存为 DXF 再批量处理。
3. 全量备份：把待处理图纸复制到 D:\cad\backup\YYYYMMDD_HHMMSS\，确认备份完整后再动手。
4. 先处理单个文件验证脚本：`msp = doc.modelspace()`，用 `msp.query('TEXT MTEXT')` 定位所有文字对象。
5. 按规则改属性：TEXT 用 `.set_height()` 或改 `.dxf.height`，MTEXT 用 `.set_char_height()`，字体改 `.dxf.style`，颜色改 `.dxf.color`（设 0 表示继承图层色）。
6. 处理块参照：用 `msp.query('INSERT')` 遍历块，递归修改块内实体（block 内文字的 .dxf.height / .dxf.color）。
7. 先在一张测试图纸上跑通，用 AutoCAD 打开确认字体、字高、颜色符合规范，再批量循环所有文件。
8. 保存为新文件（如 原文件名_已规范.dxf）而非覆盖原图，出错时可随时回滚。
9. 生成报告：统计每个文件处理文字数、跳过的锁定图层/异常对象，写入 Excel（列：文件名、TEXT 数、MTEXT 数、跳过数、状态）。

### 78. 批量优化代码冗余内容，格式化统一代码缩进规范

**细分能力点（5 条）**

1. 自动检测并清理重复代码、无用变量、空函数、注释掉的死代码、未使用 import 等冗余内容。
2. 统一代码缩进与格式规范：Python 用 black，JS/TS 用 Prettier，Java 配置通用格式化规则。
3. 通过 ESLint 等静态检查发现未使用变量、重复分支、多余导入，并给出自动修复。
4. 批量处理整个项目目录下所有源码文件，保持原有目录结构不变。
5. 修改前用 git 或备份文件做版本化，可对比 diff 一键回滚。

**可执行提示词（5 条）**

1. "用 black 格式化 D:\python_project 下所有 .py 文件，统一缩进为 4 空格、单行长度 88，先 git 提交再格式化。"
2. "对 F:\webapp 前端项目执行 eslint --fix 自动修复未使用变量和多余 import，再用 prettier --write 统一缩进 2 空格、单引号格式。"
3. "分析 C:\java_project 里的重复代码，找出复制粘贴超过 15 行的片段，提取为公共方法并替换调用处，保持功能不变。"
4. "批量删除 D:\scripts 下 Python 脚本中的空函数、被注释掉的死代码和未使用 import，改完用 git diff 生成修改清单给我确认。"
5. "给 E:\project 配置统一规范：JS 用 Prettier（缩进 2 空格）、Python 用 black（缩进 4 空格），全项目跑一遍并生成处理报告。"

**操作步骤（10 步）**

1. 初始化版本控制：在项目根目录执行 `git init`，先提交一次（`git add . && git commit -m "before format"`）作为回滚点。
2. 二次备份：将项目复制到 D:\code_backup\YYYYMMDD\ 或打一个 git 标签（`git tag backup-before-format`），双保险。
3. 安装工具：Python 执行 `pip install black`；JS/TS 执行 `npm install -D prettier eslint`；Java 可用 Eclipse 格式化配置或 google-java-format。
4. 生成统一配置：写 pyproject.toml 配置 black（line-length=88、缩进 4 空格），写 .prettierrc（printWidth、tabWidth、semi、singleQuote），配 .eslintrc 规则。
5. 先单文件试跑：`black --diff 文件.py` 查看改动，`prettier --check 文件.js` 对比差异，确认风格符合预期后再全量执行。
6. 全量格式化：`black 项目目录`，`prettier --write .`，`eslint --fix .` 自动修复可修复问题（未用变量、多余 import、重复分支）。
7. 冗余清理：用 eslint 规则 no-unused-vars、no-duplicate-imports 找出告警，配合 AI 逐个消除未使用代码。
8. 重复代码检测：让 AI 或用 SonarLint 等工具扫描项目，找出重复片段，提取公共函数/方法并替换调用处。
9. 验证功能：格式化后重新运行测试（`pytest` / `npm test` / `mvn test`），确保清理冗余没有破坏逻辑。
10. 复核提交：`git diff` 逐项复核改动，确认无误后 `git commit`，并保留一份修改前后文件数量与行数对比报告。
