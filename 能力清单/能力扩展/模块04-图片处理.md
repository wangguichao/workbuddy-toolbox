# 图片处理（模块 04）
该模块把以下能力扩展为可直接参考的子项、提示词和操作步骤。原始条数 7，共 105~140 个扩展条目。

### 9. 将一百张图片的尺寸统一为800x800，文件重命名为sku编号

**细分能力点（5 条）**

1. 支持 JPG/PNG/WEBP 等常见格式图片批量读取与统一输出。
2. 支持两种统一方式：保持纵横比补白边填充至 800x800，或居中裁剪至 800x800。
3. 读取 Excel/CSV 中的 SKU 编号列表，按文件排序顺序逐一重命名。
4. 自动校验图片数量与 SKU 编号数量是否一致，不一致时停止并提示。
5. 输出处理报告（Excel），列出每张图片处理前后的文件名与尺寸，标记失败项。

**可执行提示词（5 条）**

1. "把 D:\产品图\原图 文件夹里所有图片统一改为 800x800 像素，保持纵横比、空白处补白边，输出到 D:\产品图\成品。"
2. "读取 D:\产品图\sku清单.xlsx 里的 SKU 编号（第一列），按图片文件名排序后依次重命名为『编号.jpg』，覆盖到成品文件夹。"
3. "处理前先核对图片数量是否等于 SKU 编号数量，不相等就列出差异并停下来等我确认。"
4. "重命名规则：图片按名称排序后与 SKU 清单第一列顺序一一对应，输出格式 jpg，质量 90%。"
5. "全部处理完后生成对照表 Excel，列：原始文件名、SKU编号、处理前尺寸、处理后尺寸、是否成功。"

**操作步骤（8 步）**

1. 安装 Python 与依赖库：在命令行执行 `pip install pillow openpyxl`。
2. 准备 SKU 清单：用 Excel 建一张表，第一列填 SKU 编号，保存为 xlsx 或 csv。
3. 将 100 张原图统一放入 D:\产品图\原图 文件夹，确认文件名无重复、无损坏。
4. 编写脚本读取 SKU 编号列表，并列出原图文件名（按名称排序）。
5. 校验数量一致后，用 Pillow 逐张打开图片，使用 thumbnail 加白底画布合成 800x800（或中心裁剪）。
6. 用 `Image.save` 按 SKU 编号命名保存到成品文件夹，JPEG 质量设为 90。
7. 用 openpyxl 生成处理对照表，写入每张图的原始名、编号、尺寸。
8. 先拿 5 张试跑确认尺寸与命名正确，再全量处理，最后抽查成品。

### 26. 整理手机相册，按拍摄日期、人物、场景自动分文件夹归档

**细分能力点（5 条）**

1. 读取照片 EXIF 拍摄日期（DateTimeOriginal），无 EXIF 时用文件修改时间兜底。
2. 按"年-月"或"年-月-日"自动创建文件夹并移动归档。
3. 基于人脸识别（face_recognition/OpenCV）对同一人物的照片聚类归入同名文件夹。
4. 基于内容分类区分风景、美食、宠物、截图、文档等场景类别。
5. 自动识别截图与重复照片（哈希比对），移入待删除文件夹而非直接删除。

**可执行提示词（5 条）**

1. "帮我整理 D:\手机相册导出 里的所有照片，按拍摄年份和月份创建文件夹（如 2024-08），把照片移动进去。"
2. "把同一人物出现的照片归入同一个文件夹，人物命名先用 人物1、人物2，识别结果生成名单给我确认。"
3. "区分出截图和重复照片，移动到 D:\待删除 文件夹，不要直接删除。"
4. "没有 EXIF 拍摄日期的照片按文件修改时间归类，并在文件名里加『无EXIF』标记。"
5. "整理完成后生成一张归档说明表（原始路径 → 新路径 → 归类依据），方便我日后找回。"

**操作步骤（8 步）**

1. 安装 Python 依赖：`pip install pillow piexif opencv-python numpy`，如做人脸再装 `pip install face_recognition`。
2. 将手机相册通过 USB/网盘导出到电脑，保持原有目录结构不破坏。
3. 用 Pillow + piexif 读取每张照片 EXIF 的 DateTimeOriginal，取不到就用 os.path.getmtime 兜底。
4. 按 "YYYY-MM" 建立目标文件夹，用 shutil.move 把照片归档到对应月份。
5. 对人物归类：用 face_recognition 提取每张含人脸照片的特征向量，聚类成组并人工命名。
6. 对场景分类：用图片尺寸+颜色分布识别截图（接近屏幕分辨率、色块单一），用图像哈希比对识别重复照片。
7. 重复/截图照片移动到 D:\待删除 目录，同时生成待删清单。
8. 先在副本目录试跑一小批，核对移动结果无误后再对全量相册执行，最后导出归档说明表。

### 30. 批量去除图片水印、多余边框，统一白底背景

**细分能力点（5 条）**

1. 支持文字水印与 Logo 水印两种去除方式。
2. 支持按固定位置/区域批量去除（如右下角固定位置）。
3. 自动检测并裁剪图片四周多余黑边、白边。
4. 将裁剪后背景统一填充为纯白色（RGB 255,255,255）。
5. 去除效果不佳的图片自动单独标记，供人工复核或补裁。

**可执行提示词（5 条）**

1. "批量去掉 D:\图片目录 里所有图片右下角约 200x80 像素区域的文字水印，用 OpenCV 的 inpaint 方法。"
2. "自动裁剪每张图片四周的多余黑边，然后统一把背景填充成纯白色。"
3. "处理前先用颜色阈值自动检测水印位置和大小，把标注框的预览图发给我确认。"
4. "水印去除后模糊或有残留的图片，单独复制到 D:\待人工处理，并附处理前后对比图。"
5. "所有图片统一输出为 JPG，尺寸不变，质量 95%，输出到成品文件夹。"

**操作步骤（8 步）**

1. 安装 Python 依赖：`pip install opencv-python numpy pillow`。
2. 抽样查看若干张原图，总结水印位置、颜色、大小的规律。
3. 编写脚本用阈值分割或人工指定矩形框生成水印掩码（mask）。
4. 用 `cv2.inpaint` 对掩码区域做修复，去除水印文字/Logo。
5. 用边缘检测（Canny）或亮度统计定位四周边框，计算裁剪范围并裁剪。
6. 把裁剪后边缘区域用 `cv2.rectangle` 或 Pillow 填充为白色背景。
7. 每张图生成"处理前/处理后"对比图，便于验收。
8. 批量处理完成后再逐批抽查，水印残留严重的调整掩码重新处理，无法去除的列入清单说明。

### 37. 批量生成证件照，切换白底 / 蓝底 / 红底，调整标准尺寸

**细分能力点（5 条）**

1. 用 rembg 自动去除人像背景，得到透明底图。
2. 一键填充白底、蓝底、红底三种底色。
3. 支持标准证件照尺寸：1 寸（295×413）、2 寸（413×579）、护照等。
4. 自动居中定位人脸并调整头部留白比例。
5. 支持排版打印：把多张证件照排版到一张 6 寸相纸上。

**可执行提示词（5 条）**

1. "把 D:\证件照\原图 里每个人的照片自动抠出人像，生成 1 寸白底证件照，像素 295×413，输出到成品文件夹。"
2. "同一张人像同时生成白底、蓝底、红底三个版本，文件名带底色后缀（如 张三_白底.jpg）。"
3. "把 8 张 1 寸证件照排版到一张 6 寸相纸（300dpi，1200×1800 像素）上，方便打印后裁剪。"
4. "处理前先检测每张图是否有人脸，没有脸或脸不完整的放到问题文件夹。"
5. "批处理 D:\员工照片 文件夹，全部统一成 2 寸蓝底证件照 413×579 像素。"

**操作步骤（7 步）**

1. 安装 Python 依赖：`pip install rembg pillow opencv-python`（rembg 首次运行会自动下载模型）。
2. 用 rembg 对每张人像批量抠图，输出带透明通道的 PNG。
3. 按需用 Pillow 在透明层下填充白底（255,255,255）、蓝底（67,142,219）或红底（255,0,0）。
4. 用 Pillow 把人像缩放、居中裁剪到目标像素尺寸（1 寸 295×413、2 寸 413×579）。
5. 用 `ImageDraw` 按证件照规则微调人脸位置与头部留白比例。
6. 用 Pillow 新建 6 寸画布（1200×1800px），把多张证件照按 2×4 网格排版输出。
7. 抽查人脸边缘是否有抠图残影，如边缘发白可做 1-2px 边缘羽化后重新输出。

### 42. 批量识别图片文字，导出可编辑 Word 文档，修正识别错别字

**细分能力点（5 条）**

1. 支持中英文混排图片文字识别（PaddleOCR 中文效果好，或 Tesseract）。
2. 按"从上到下、从左到右"的阅读顺序还原排版，分段落写入 Word。
3. 自动修正常见错别字（同音字、形近字，如"已/己/巳"、"未/末"）。
4. 支持按置信度标记低可信度文字，方便人工复核。
5. 输出可编辑 docx 文档，并可附带原文截图对照。

**可执行提示词（5 条）**

1. "批量识别 D:\扫描件 文件夹里所有图片上的文字，按阅读顺序合并，导出为一个可编辑的 Word 文档。"
2. "用 PaddleOCR 识别，每张图片识别的内容单独成一个段落，文档开头加目录索引。"
3. "识别后自动修正常见错别字，比如 巳/已、未/末、陪/赔，把修正过的词用黄色高亮标出。"
4. "识别置信度低于 0.85 的文字标黄并加下划线，让我人工核对。"
5. "在 Word 里每段识别文字下方插入对应原图截图，方便逐段对照检查。"

**操作步骤（8 步）**

1. 安装 Python 依赖：`pip install paddleocr paddlepaddle python-docx`（或 Tesseract + pytesseract）。
2. 把待识别图片按页顺序重命名放入文件夹，确保顺序正确。
3. 用 PaddleOCR 逐张识别，得到文本、坐标框与置信度。
4. 按坐标（y 再 x）排序，还原从上到下、从左到右的阅读顺序。
5. 拼接文本，用 python-docx 写入 Word，设置字体（宋体/等线）与段落样式。
6. 建立易错字映射表做规则修正，并对修正项与低置信度项加高亮。
7. 抽样 10 张图人工核对准确率，必要时调整语言模型或放大预处理。
8. 批量导出最终 docx，另附一份"修正对照表"（原文错误词 → 修正词）便于审核。

### 70. 批量给图片添加统一品牌水印，调整水印位置透明度

**细分能力点（5 条）**

1. 支持 PNG Logo 水印与文字水印两种类型。
2. 支持九宫格任意位置（左上/右上/居中/右下等）加边距控制。
3. 支持透明度调节（alpha 通道）与平铺水印效果。
4. 批量应用同一套水印参数，保证全批次风格统一。
5. 先输出预览图确认效果，再全量处理，原图自动备份。

**可执行提示词（5 条）**

1. "给 D:\产品图 里所有图片添加 D:\素材\品牌logo.png 水印，位置右下角，边距 20 像素，透明度 60%。"
2. "用文字水印『XX科技 © 2026』，字体微软雅黑、大小自适应图片宽度 8%，透明度 30%，右下角。"
3. "把文字水印做成平铺背景效果，间隔 200 像素，整体透明度 10%，不遮挡主要内容。"
4. "先只处理前 3 张生成预览，我确认水印大小和位置满意后再批量处理剩余图片。"
5. "处理前先把原图备份到 D:\原图备份，处理后统一输出 JPG 质量 90%，覆盖成品文件夹。"

**操作步骤（7 步）**

1. 准备水印素材：透明背景的 PNG Logo，或确定文字内容、字体与字号。
2. 安装 Python 依赖：`pip install pillow`。
3. 编写脚本读取每张原图，创建独立水印图层（ImageDraw 绘制文字，或直接贴 PNG Logo）。
4. 按九宫格坐标与边距计算水印插入位置，用 alpha 通道调整透明度。
5. 用 `Image.alpha_composite` 合成水印与原图，转 RGB 后保存为 JPG。
6. 先处理 3 张生成预览，检查水印是否遮挡主体、清晰度是否合适。
7. 确认后全量处理；处理前用 shutil.copy2 把原图备份到备份文件夹。

### 79. 识别票据二维码，批量读取信息录入电子台账表格

**细分能力点（5 条）**

1. 用 pyzbar 识别票据上的二维码与条形码。
2. 自动解析二维码内容（纯文本、URL、JSON 等格式）。
3. 自动定位票据中的二维码区域，倾斜或过小时先校正放大再识别。
4. 识别结果批量写入 Excel 台账，按票据号自动去重。
5. 识别失败或模糊的票据单独标记原因，支持人工补录。

**可执行提示词（5 条）**

1. "批量扫描 D:\票据 文件夹里所有票据图片上的二维码，把内容逐条录入台账 Excel。"
2. "识别发票右下角二维码，解析出票据号、金额、开票日期、销售方，填入台账对应列。"
3. "对二维码太小或倾斜的票据，先用 OpenCV 定位放大、透视校正，再识别。"
4. "识别失败的票据单独放一个 Sheet 并标注失败原因，方便我人工补录。"
5. "写入台账时按票据号去重，同一票据号只保留第一条，重复的单独列出提醒。"

**操作步骤（7 步）**

1. 安装 Python 依赖：`pip install pyzbar pillow opencv-python openpyxl`（Windows 需装 ZBar，可用 pip 安装 pyzbar 自带 DLL 或单独装 ZBar）。
2. 抽样查看票据样本，确认二维码/条形码的固定位置与大小规律。
3. 用 OpenCV 定位二维码区域，必要时做灰度化、透视校正并放大到合适尺寸。
4. 用 pyzbar 逐张解码，提取二维码内容并解析成结构化字段（票据号、金额、日期等）。
5. 校验字段格式（金额为数字、日期合法、票据号非空），不合法字段标记。
6. 用 openpyxl 把结果写入台账模板，按票据号去重，失败项写入单独 Sheet。
7. 随机抽查 20 张确认识别率，识别率低时调整预处理参数（亮度、对比度、缩放倍数）后重跑。
