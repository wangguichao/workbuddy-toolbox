### 56. 自动编写单元测试代码，适配 Java、Python、JS 开发项目

**细分能力点（5 条）**

1. 支持 Java（JUnit 5 + Maven/Gradle）、Python（pytest）、JS（Jest/Vitest）三大技术栈自动生成测试骨架。
2. 解析被测类/函数的入参、返回值、边界条件，自动推导"正常、边界、异常"三类测试场景。
3. 自动生成测试数据，含空值 null/""、越界值、极大数据、特殊字符，并计算断言预期结果。
4. 生成的测试文件放入正确目录并自动执行，输出通过/失败统计，失败用例标注失败原因。
5. 支持批量扫描整个项目目录，按包/模块结构为所有公共方法生成对应测试文件。

**可执行提示词（5 条）**

1. "为 E:\work\calc.js 生成单元测试，补充除以零、负数、极大数用例，运行后按函数名汇总失败项。"
2. "扫描 D:\workspace 项目，为所有公共类和函数批量生成单元测试并运行，输出通过/失败统计报告。"
3. "先检查 D:\workspace 现有测试的覆盖情况，找出还没覆盖的核心函数补齐测试，运行后反馈覆盖率变化。"
4. "给项目配置统一测试规范：Java、Python、JS 都按正常、边界、异常三档生成用例，目录和命名按各语言约定。"
5. "每周一 9:00 自动为 D:\workspace 新增的代码生成单元测试并运行，把结果和失败原因发我。"

**操作步骤（8 步）**

1. 把项目放到固定位置，如 D:\workspace\my-service，确认它属于 Java、Python 或 JS 项目。
2. 向 Workbuddy 发指令：「为 D:\workspace\my-service 的 Java 项目生成单元测试，覆盖正常、边界、异常场景，放到对应测试目录并运行，反馈通过/失败统计。」
3. Workbuddy 确认生成范围：全部公共类还是指定类、测试目录位置、是否自动运行测试并生成报告；按需补充，如「全部公共类，运行测试，失败用例标注原因」。
4. 确认后 Workbuddy 自动解析源码、生成测试文件、执行测试，全程无需你安装任何测试框架或手写测试代码。
5. 查看 Workbuddy 返回的测试结果：通过的用例数、失败用例及原因。
6. 对失败用例，直接告诉 Workbuddy「修复 xx 测试」或「调整断言」，它会自动修正并重新运行。
7. 想让测试持续有效，发指令「每周一 9:00 自动为新代码生成测试并运行，把报告发我」，由 Workbuddy 定时执行。
8. 需要时让 Workbuddy 把测试覆盖报告整理给你，说明覆盖了哪些函数、还遗漏哪些。

### 68. 批量修改 CAD 图纸文字标注，统一字号、字体、颜色规范

**细分能力点（5 条）**

1. 支持遍历整个文件夹下的 DWG/DXF 图纸，批量处理文字标注对象。
2. 能区分并处理 TEXT 单行文字、MTEXT 多行文字、块参照（INSERT）内的属性文字。
3. 按图层、文字类型或样式分别设定字体、字高、颜色的统一规则。
4. 修改前自动备份原图，处理失败可回滚，避免损坏图纸。
5. 生成处理报告，统计每个文件修改文字数量及跳过项（如锁定图层）。

**可执行提示词（5 条）**

1. "处理 D:\cad\图纸\示例.dxf，把全部标注文字统一为字高 2.5、颜色黄色。"
2. "批量处理 D:\cad\图纸\ 下所有 DXF 图纸，把单行、多行标注文字统一为字高 2.5、字体宋体、颜色黄色。"
3. "先扫描 C:\cad_files 所有图纸，统计出不符合字高和颜色规范的文字数量及位置，列给我确认后再批量修改。"
4. "把 E:\工程图 的文字按规范统一：尺寸标注蓝色、注释绿色、标题黄色、字体 Arial、字高不小于 2.5，先备份再另存新文件。"
5. "每周五 18:00 自动扫描 F:\设计图 新增图纸，按规范统一文字标注，完成后发我处理报告。"

**操作步骤（8 步）**

1. 把待处理图纸整理到 D:\cad\图纸\ 文件夹，DWG 或 DXF 格式均可。
2. 向 Workbuddy 发指令：「批量处理 D:\cad\图纸\ 下所有图纸，把单行、多行标注文字统一为字高 2.5、字体宋体、颜色黄色。」
3. Workbuddy 确认处理规则：文字类型范围（是否含块内属性文字）、是否需要先备份、是否另存新文件；按需补充，如「先备份，另存为「_规范」新文件，含块内文字」。
4. 确认后 Workbuddy 自动完成备份、遍历图纸、统一文字属性，全程无需你安装任何 CAD 处理软件或编写脚本。
5. 处理完成，Workbuddy 给出修改报告：每个文件改了哪些文字、跳过了哪些图层。
6. 打开一两张图纸抽查，发现个别没改到位的，直接说「第 xx 张图的标题文字还没统一，修一下」，Workbuddy 自动修正。
7. 想让规范持续执行，发指令「每周五 18:00 自动扫描新增图纸并统一标注，发我处理报告」，由 Workbuddy 定时处理。
8. 需要保留原版时，要求 Workbuddy「把原图也备份一份到 D:\cad\backup 文件夹」。

### 78. 批量优化代码冗余内容，格式化统一代码缩进规范

**细分能力点（5 条）**

1. 自动检测并清理重复代码、无用变量、空函数、注释掉的死代码、未使用的引用等冗余内容。
2. 统一代码缩进与格式规范，自动适配各语言的主流格式规则。
3. 通过静态检查发现未使用变量、重复分支、多余导入，并给出自动修复。
4. 批量处理整个项目目录下所有源码文件，保持原有目录结构不变。
5. 修改前用 git 或备份文件做版本化，可对比 diff 一键回滚。

**可执行提示词（5 条）**

1. "格式化 D:\python_project 下所有 Python 文件，统一缩进 4 空格、单行长度 88，先备份再处理。"
2. "对 F:\webapp 前端项目批量修复未使用变量和多余导入，统一缩进 2 空格、单引号格式。"
3. "先扫描 C:\java_project 的重复代码，把超过 15 行的重复片段和位置列给我，确认后再提取为公共方法替换。"
4. "清理 D:\scripts 下 Python 脚本的空函数、注释掉的死代码和未使用导入，生成修改清单供我逐项确认。"
5. "每月 1 号自动对 E:\project 全项目做一次格式化和冗余清理，规范保持一致，完成后发处理报告。"

**操作步骤（8 步）**

1. 把项目放到固定位置，如 F:\webapp，先向 Workbuddy 说明技术栈（前端 JS、后端 Python 等）。
2. 向 Workbuddy 发指令：「对 F:\webapp 项目统一代码格式，前端缩进 2 空格、Python 缩进 4 空格，自动修复未使用变量和多余导入，先做版本备份。」
3. Workbuddy 确认处理范围：全项目还是指定目录、格式细节、是否需要生成修改清单；按需补充，如「全项目，生成修改清单」。
4. 确认后 Workbuddy 自动备份、格式化、清理冗余代码，全程无需你安装格式化工具或配置环境。
5. Workbuddy 返回修改清单（改动文件、行数、清理项），你逐项确认。
6. 发现有误改的，直接说「把 X 文件的改动回滚」或「这里不该删，恢复」，Workbuddy 自动处理。
7. Workbuddy 自动运行项目测试，确认清理冗余没有破坏功能，并给出结果。
8. 后续想定期维护，发指令「每月 1 号自动做一次全项目格式化与冗余清理，完成后发报告」，由 Workbuddy 定时执行。
