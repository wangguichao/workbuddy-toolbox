# 扩展模板规范

本项目每条能力都按统一结构展开，本文档定义该结构，供贡献者新增或完善内容时参考。

> **核心原则**：所有内容基于 Workbuddy 使用。用户只需向 Workbuddy 发送指令即可完成任务，文档中的提示词与操作步骤都围绕「与 Workbuddy 对话」展开，不要求用户自行搭建环境。

## 一、章节结构

每个能力章节使用三级标题，格式如下：

```markdown
### {全局编号}. {能力标题}

**细分能力点（5 条）**

1. {具体可执行的能力点}
2. {具体可执行的能力点}
3. {具体可执行的能力点}
4. {具体可执行的能力点}
5. {具体可执行的能力点}

**可执行提示词（5 条）**

1. "{直接发送给 Workbuddy 的指令，目标导向、含必要参数}"
2. "{直接发送给 Workbuddy 的指令，目标导向、含必要参数}"
3. "{直接发送给 Workbuddy 的指令，目标导向、含必要参数}"
4. "{直接发送给 Workbuddy 的指令，目标导向、含必要参数}"
5. "{直接发送给 Workbuddy 的指令，目标导向、含必要参数}"

**操作步骤（5~10 步）**

1. {向 Workbuddy 发送指令，并说明它会如何回应}
2. {Workbuddy 确认/询问信息，你如何补充}
3. {确认后 Workbuddy 自动完成，你无需搭建}
4. {你如何检查/验证结果}
5. {如何改配置、定时、暂停等后续管理}
...
```

## 二、写作要求

### 细分能力点

- 把这条能力拆成 **5 个**更小的可执行子任务。
- 每个子任务要具体，例如「支持 JPG/PNG/PDF 多种格式」「自动提取发票号、金额、开票日期」。
- 5 点应覆盖能力的核心环节（输入、处理、校验、分类、输出）。

### 可执行提示词

- **5 条**，每条约 30~80 字。
- **目标导向**：描述「要什么结果」，而不是「用什么技术」。不要出现技术库名（如 pandas、akshare、PaddleOCR、yagmail）或编程细节——这些由 Workbuddy 自行决定实现方式。
- 包含必要参数：路径（如 `D:\数据\`）、时间（如「每天 14:30」）、格式（如「2026-06-28」）、数量阈值（如「降价超 5%」）、邮箱地址等。
- 用第一人称，像用户直接对 AI 说话，例如「帮我……」「设置……」「批量……」「校验……」「对比……」。提示词外不用加引号以外的说明。
- 5 条提示词应覆盖不同场景：一次处理、批量处理、定时任务、校验/复核、流程化。

### 操作步骤（对话式执行流程）

- **5~10 步**，展示用户与 Workbuddy 的完整交互过程，每步都是对话中的一环。
- 常见节奏：**发指令 → Workbuddy 确认/询问 → 你补充信息 → Workbuddy 自动完成 → 你检查结果 → 后续管理（改配置/定时/暂停）**。
- 强调「由 Workbuddy 自动完成技术实现」，避免出现让用户手动安装软件、写代码、配置环境的表述。
- 涉及外部平台（邮箱、网盘、网银导出等）时，保留必要的用户操作（如导出账单、整理文件到指定文件夹）与合规提示。
- 涉及删除、加密、批量替换等敏感操作时，提示先备份、确认后再执行。

## 三、硬性校验

提交内容前请自查：

- [ ] 章节标题编号全局唯一（`### 编号. 标题`）
- [ ] 三个小节标题齐全：细分能力点、可执行提示词、操作步骤
- [ ] 细分能力点恰好 5 条
- [ ] 可执行提示词恰好 5 条，且均为目标导向（不含技术库名）
- [ ] 操作步骤 5~10 步，且为对话式执行流程（围绕向 Workbuddy 发指令）
- [ ] 合计条目数在 **15~20** 之间
- [ ] 全文简体中文，表述具体可操作
- [ ] 新增编号已同步登记到 `能力清单/分类整理.md` 与 `docs/分类总览.md`

## 四、示例

```markdown
### 14. 扫描发票截图，自动提取信息填好报销表

**细分能力点（5 条）**

1. 支持 JPG/PNG/PDF 多种格式发票截图识别。
2. 自动提取发票号、开票日期、金额、税号、销售方等关键字段。
3. 对识别结果做格式校验（金额、日期合法性）。
4. 按公司/月份自动归类到报销台账。
5. 生成报销汇总表并导出 Excel。

**可执行提示词（5 条）**

1. "识别这张发票图片 D:\报销\发票.jpg，提取发票号、开票日期、价税合计金额、销售方名称，填入报销表模板。"
2. "批量识别 D:\报销发票\ 目录下所有 JPG/PNG/PDF 发票，提取发票号、日期、金额、税额、销售方、类别，输出成 Excel 报销台账。"
3. "把识别出的发票按『交通、餐饮、办公、其他』四类归类，金额保留两位小数，生成月度报销汇总表。"
4. "检查这批发票里金额为负数或日期超出本月范围的记录，单独列一个工作表标黄，方便我人工核对。"
5. "每月月底自动扫描 D:\报销发票\ 文件夹，识别新增发票并更新报销台账，生成当月报销清单发给我。"

**操作步骤（6 步）**

1. 把需要报销的发票截图统一放到 D:\报销发票\ 文件夹。
2. 向 Workbuddy 发送指令：「帮我把 D:\报销发票\ 文件夹里的发票批量识别，提取发票号、开票日期、金额、销售方，整理成报销台账 Excel。」
3. Workbuddy 会确认输出格式：台账列名、保存路径、是否按月份/类别归档，按需补充（如"保存到 D:\报销台账\，按月份分表"）。
4. 确认后，Workbuddy 自动完成识别、校验、生成台账，你无需手动安装识别软件或写脚本。
5. 打开生成的台账检查字段准确性，有识别错的地方直接指出来让 Workbuddy 修正。
6. 想定时处理就告诉 Workbuddy：「每周五 17:00 自动扫描新增发票，更新台账并发我当周报销清单。」
```

该示例共 5 + 5 + 6 = **16 条**，符合 15~20 的要求。
